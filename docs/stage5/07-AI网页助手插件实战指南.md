# 07 - AI 网页助手插件实战指南

## 项目目标

本项目要实现一个简化版 AI 网页助手插件。

核心能力：

```text
选中文字自动弹出浮层
解释选中文本
翻译选中文本
总结当前页面
```

学习目标：

- 理解 Chrome Extension 的完整数据流
- 掌握 Selection API 和浮层定位
- 掌握 Shadow DOM 样式隔离
- 掌握 Content Script 与 Background Worker 的消息通信
- 学会从网页提取上下文并组装 AI Prompt
- 学会安全渲染 AI 返回的 HTML 结果

---

## 1. 交互设计

与传统 Popup 式插件不同，本项目采用**选中即触发**的交互模式：

```text
用户在网页上选中文字
  ↓
mouseup 事件触发
  ↓
选区上方自动弹出浮层（Shadow DOM 隔离样式）
  ↓
浮层显示：解释 | 翻译 | 总结页面
  ↓
用户点击按钮
  ↓
浮层变为结果面板，展示 AI 回复（HTML 富文本）
```

为什么不用 Popup：

```text
Popup 式：
  用户需要点击图标 → 点击按钮 → 结果在 Popup 中展示
  用户视线在 Popup 和页面之间切换

浮层式：
  用户选中文字 → 浮层直接出现在文字上方
  操作路径更短，视线不用离开阅读区域
```

```text
code/ai-web-assistant/
├── manifest.json       # Manifest V3 配置
├── background.js       # Service Worker：处理 AI API 调用
├── content.js          # Content Script：选区检测、浮层 UI、结果展示
├── content.css         # Content Script 基础样式
├── popup.html          # 点击图标的提示页（设置入口）
├── popup.js            # Popup 逻辑（仅设置链接）
├── options.html        # 设置页：配置 API Key 和模型参数
├── options.js          # 设置页逻辑
└── icons/              # 插件图标
```

职责划分：

```text
content.js（核心）
  mouseup 监听 → 获取选区和坐标
  浮层 UI（Shadow DOM 隔离）
  发消息给 background.js 调 API
  渲染 AI 结果（HTML 富文本 + 白名单过滤）

background.js
  接收 AI_REQUEST 消息
  从 chrome.storage 读取配置
  调用 AI API
  返回结果

popup.js
  简单提示页 + 设置入口

options.js
  管理 API Key、Base URL、模型名称、Max Tokens
```

  "name": "AI Web Assistant",
  "version": "0.1.0",
  "description": "Summarize, translate, and explain web pages with AI.",
  "action": {
    "default_popup": "popup.html"
  },

  "host_permissions": ["https://open.bigmodel.cn/*"],
  "background": {
    "service_worker": "background.js"
  },
  "content_scripts": [
    {
      "matches": ["<all_urls>"],
      "js": ["content.js"],
      "css": ["content.css"]
    }
  ],
  "options_page": "options.html"

权限说明：

| 权限 | 用途 |
|------|------|
| `activeTab` | 获取当前标签页信息 |

| `scripting` | 动态注入 Content Script（处理已打开的页面） |
| `host_permissions` | 允许 Background Worker 访问指定 API 域名 |

## 4. 核心技术点 1：Selection API 与浮层定位

### 检测选区

```js
document.addEventListener("mouseup", () => {
  setTimeout(() => {
    const sel = window.getSelection();
    const text = sel?.toString().trim();
    if (!text || text.length < 2) return;

    const rect = sel.getRangeAt(0).getBoundingClientRect();
    showToolbar(rect);
  }, 10);
});
```

三个要点：

```text
1. mouseup 而不是 click
   click 在某些场景下选区已丢失，mouseup 更可靠

2. setTimeout 10ms
   浏览器选区更新在 mouseup 之后，需要短暂延迟确保状态正确

3. getBoundingClientRect()
   返回选区相对视口的坐标，用于定位浮层
```

### 定位浮层

```js
function positionPanel(rect, estimatedHeight) {
  let top = rect.top + window.scrollY - estimatedHeight - 10;
  let left = rect.left + window.scrollX + rect.width / 2 - 180;

  // 如果超出顶部，改为显示在选区下方
  if (top < window.scrollY) {
    top = rect.bottom + window.scrollY + 8;
  }

  // 水平方向不超出页面
  left = Math.max(8, Math.min(left, window.innerWidth - 380));
}
```

## 5. 核心技术点 2：Shadow DOM 样式隔离

页面上的 CSS 可能影响注入的浮层。用 Shadow DOM 实现完全隔离：

```js
function createPanel() {
  const host = document.createElement("div");
  host.id = "ai-wa-host";

  const shadow = host.attachShadow({ mode: "closed" });
  shadow.innerHTML = `
    <style>
      /* 这里的样式完全不受页面影响 */
      .toolbar { background: #fff; border-radius: 10px; ... }
      button { font-size: 12px; ... }
    </style>
    <div id="content"></div>
  `;

  document.body.appendChild(host);
  return { host, shadow, content: shadow.getElementById("content") };
}
```

隔离效果：

```text
外部页面 CSS            Shadow DOM 内部
┌─────────────┐        ┌─────────────┐
│ div { ... } │  ✗ 不穿透  │ .toolbar {} │
│ body { ... }│  ✗ 不穿透  │ button {}   │
└─────────────┘        └─────────────┘
```

`mode: "closed"` 意味着外部 JS 无法通过 `host.shadowRoot` 访问内部 DOM。

## 6. 核心技术点 3：消息通信与 API 调用

### Content Script 发消息给 Background Worker

```js
// content.js
async function callAI(systemPrompt, userMessage) {
  const response = await chrome.runtime.sendMessage({
    type: "AI_REQUEST",
    payload: { systemPrompt, userMessage },
  });

  if (!response?.ok) {
    throw new Error(response?.error || "Unknown error");
  }

  return response.result;
}
```

### Background Worker 接收并处理

```js
// background.js
chrome.runtime.onMessage.addListener((message, sender, sendResponse) => {
  if (message.type === "AI_REQUEST") {
    const { systemPrompt, userMessage } = message.payload;

    callAI(systemPrompt, userMessage)
      .then(result => sendResponse({ ok: true, result }))
      .catch(error => sendResponse({ ok: false, error: error.message }));

    return true;  // 异步 sendResponse 必须 return true
  }
});
```

### API 调用

Background Worker 使用原生 `fetch` 调用 Anthropic 兼容 API：

```js
async function callAI(systemPrompt, userMessage) {
  const config = await getConfig();  // 从 chrome.storage 读取

  const response = await fetch(`${config.apiBaseURL}/v1/messages`, {
    method: "POST",
    headers: {
      "x-api-key": config.apiKey,
      "anthropic-version": "2023-06-01",
      "content-type": "application/json",
    },
    body: JSON.stringify({
      model: config.model,
      max_tokens: config.maxTokens,
      system: systemPrompt,
      messages: [{ role: "user", content: userMessage }],
    }),
  });

  const data = await response.json();
  return data.content
    .filter(block => block.type === "text")
    .map(block => block.text)
    .join("\n");
}
```

### 完整数据流

```text
用户选中文字 → mouseup
  ↓
content.js: window.getSelection() → 选中文本 + 坐标
  ↓
content.js: chrome.runtime.sendMessage({ type: "AI_REQUEST" })
  ↓
background.js: 收到消息 → fetch 调用 AI API
  ↓
background.js: sendResponse({ ok: true, result: "..." })
  ↓
content.js: 收到结果 → sanitizeHtml() → innerHTML 渲染到浮层
```

## 7. 核心技术点 4：Prompt 设计与 HTML 输出

要求 AI 用 HTML 格式输出，而不是 markdown，这样可以更灵活地控制富文本展示：

### 总结页面 Prompt

```text
你是网页内容总结助手。请用中文输出：核心结论、关键要点、值得注意的细节。
使用 HTML 格式：<h3> 作为小标题，<b> 加粗关键词，<mark> 高亮重点，<ul><li> 列举要点。
不要输出 markdown 语法。保持简洁，不要重复原文。
```

### 解释选区 Prompt

```text
你是阅读辅助助手。请用中文解释用户选中的文本，说明其含义和上下文中的作用。
使用 HTML 格式输出，可以用 <b> 加粗关键词，<mark> 高亮重点，<p> 分段，<ul><li> 列举要点。
不要输出 markdown 语法。简洁明了。
```

### 为什么要求 HTML 而不是 markdown

```text
markdown 输出 → 需要额外引入 markdown 解析库 → 增加插件体积
HTML 输出     → 浏览器原生支持 → 直接渲染，零依赖
```

## 8. 核心技术点 5：HTML 安全渲染

AI 返回的 HTML 不能直接用 `innerHTML`，需要白名单过滤：

```js
const ALLOWED_TAGS = new Set([
  "b", "strong", "i", "em", "u", "mark",
  "p", "br", "ul", "ol", "li", "h3", "h4",
  "blockquote", "code", "span"
]);

function sanitizeHtml(raw) {
  const doc = new DOMParser().parseFromString(raw, "text/html");

  const walk = (node) => {
    const remove = [];
    for (const child of node.childNodes) {
      if (child.nodeType === Node.ELEMENT_NODE) {
        if (!ALLOWED_TAGS.has(child.tagName.toLowerCase())) {
          remove.push(child);
        } else {
          for (const attr of [...child.attributes]) {
            child.removeAttribute(attr.name);
          }
          walk(child);
        }
      }
    }
    remove.forEach(el => el.replaceWith(...el.childNodes));
  };

  walk(doc.body);
  return doc.body.innerHTML;
}
```

原则：

```text
错误信息 → textContent（自动转义）
AI 结果 → sanitizeHtml() 过滤后 innerHTML
绝不直接 innerHTML = aiResponse
```

## 9. 页面正文提取

```js
function extractReadableText() {
  const root =
    document.querySelector("article") ||
    document.querySelector("main") ||
    document.body;

  const clone = root.cloneNode(true);
  clone.querySelectorAll("script, style, nav, footer, aside, header")
    .forEach(node => node.remove());

  return clone.innerText
    .replace(/\n{3,}/g, "\n\n")
    .trim()
    .slice(0, 12000);
}
```

提取策略：

```text
1. 优先读 article 标签（博客、新闻通常在这里）
2. 其次读 main 标签
3. 兜底读 body
4. 删除 script、style、nav、footer、aside、header
5. 合并多余空行
6. 截断到 12000 字符（避免 Token 爆炸）
```

## 10. Content Script 动态注入

`content_scripts` 只在页面加载时自动注入。如果用户在插件安装前就打开了页面，需要手动注入：

```js
// popup.js
try {
  return await chrome.tabs.sendMessage(tab.id, { type: "GET_PAGE_CONTEXT" });
} catch {
  await chrome.scripting.executeScript({
    target: { tabId: tab.id },
    files: ["content.js"]
  });
  return await chrome.tabs.sendMessage(tab.id, { type: "GET_PAGE_CONTEXT" });
}
```

## 11. 错误处理

需要覆盖的场景：

```text
页面不允许注入 Content Script（chrome:// 页面）
选区为空时点击解释/翻译
API Key 未配置
API 请求失败（网络错误、额度用尽）
模型返回空结果
文本过长超出上下文
```

## 12. 安全和隐私注意事项

```text
权限最小化：只声明 activeTab、storage、scripting
API Key 存 chrome.storage，不硬编码在代码中
用户点击按钮后才读取和发送页面内容
AI 返回内容经白名单过滤后再渲染
不收集浏览历史
host_permissions 限定到具体 API 域名
```
