# 日志监控与可观测性

## 为什么 AI 应用需要可观测性

传统应用的日志主要关注"请求进来了、数据库查了、响应返回了"。AI 应用多了一层不确定性：

- **LLM 调用慢不慢**？一次请求耗时多少？
- **Token 用了多少**？每天花多少钱？
- **输出质量如何**？返回空内容或格式错误的比例？
- **用户在问什么**？哪些类型的问题最多？
- **调用链路是什么**？从用户请求到最终响应经过了哪些步骤？

没有日志和监控，AI 应用上线后就是"黑盒"。

---

## 一、可观测性三支柱

```
Logging（日志）     → 发生了什么？
Metrics（指标）     → 发生了多少次？多快？多慢？
Tracing（链路追踪） → 请求经过了哪些环节？
```

## 二、Logging：结构化日志

### 2.1 为什么不用 print

```python
# 不好：非结构化日志
print(f"用户 {user_id} 问了：{question}")
print(f"LLM 回答：{answer}")
```

这种日志没法搜索、没法统计、没法告警。

### 2.2 结构化日志

每条日志是一条 JSON 记录，包含固定字段：

```python
import logging
import json
import time
from datetime import datetime


class StructuredLogger:
    def __init__(self, name):
        self.logger = logging.getLogger(name)
        self.logger.setLevel(logging.INFO)

        handler = logging.StreamHandler()
        handler.setFormatter(logging.Formatter("%(message)s"))
        self.logger.addHandler(handler)

    def _log(self, level, event, **kwargs):
        record = {
            "timestamp": datetime.utcnow().isoformat(),
            "level": level,
            "event": event,
            **kwargs,
        }
        self.logger.log(
            getattr(logging, level.upper()),
            json.dumps(record, ensure_ascii=False),
        )

    def info(self, event, **kwargs):
        self._log("info", event, **kwargs)

    def warning(self, event, **kwargs):
        self._log("warning", event, **kwargs)

    def error(self, event, **kwargs):
        self._log("error", event, **kwargs)


log = StructuredLogger("ai_app")
```

### 2.3 LLM 调用日志

记录每一次 LLM 调用的关键信息：

```python
async def logged_llm_call(messages, model="claude-sonnet-4-6", **kwargs):
    """带日志的 LLM 调用"""
    request_id = kwargs.get("request_id", "unknown")
    start_time = time.time()

    log.info("llm.request", request_id=request_id, model=model,
             message_count=len(messages))

    try:
        response = await call_llm(messages, model=model, **kwargs)
        duration = time.time() - start_time

        log.info("llm.response",
                 request_id=request_id,
                 model=model,
                 duration_ms=round(duration * 1000, 2),
                 input_tokens=response.usage.input_tokens,
                 output_tokens=response.usage.output_tokens,
                 stop_reason=response.stop_reason)

        return response

    except Exception as e:
        duration = time.time() - start_time
        log.error("llm.error",
                  request_id=request_id,
                  model=model,
                  duration_ms=round(duration * 1000, 2),
                  error_type=type(e).__name__,
                  error_message=str(e))
        raise
```

## 三、Metrics：关键指标

### 3.1 AI 应用需要监控的指标

| 指标 | 含义 | 告警阈值 |
|------|------|----------|
| request_total | 总请求数 | - |
| request_success_rate | 成功率 | < 95% |
| request_latency_p50/p95/p99 | 延迟分位数 | P99 > 30s |
| token_input_total | 输入 Token 总量 | - |
| token_output_total | 输出 Token 总量 | - |
| token_cost_total | 估算费用 | 超日预算 |
| fallback_triggered | 降级触发次数 | > 10次/小时 |
| guardrail_blocked | Guardrails 拦截次数 | 突增 |
| error_by_type | 按类型统计错误 | 429 > 50次/小时 |

### 3.2 简单的指标收集器

```python
from collections import defaultdict
import time


class MetricsCollector:
    def __init__(self):
        self._counters = defaultdict(int)
        self._timings = defaultdict(list)
        self._start_time = time.time()

    def increment(self, metric, value=1, tags=None):
        key = self._make_key(metric, tags)
        self._counters[key] += value

    def timing(self, metric, value_ms, tags=None):
        key = self._make_key(metric, tags)
        self._timings[key].append(value_ms)

    def _make_key(self, metric, tags=None):
        if not tags:
            return metric
        tag_str = ",".join(f"{k}={v}" for k, v in sorted(tags.items()))
        return f"{metric}{{{tag_str}}}"

    def get_summary(self):
        """获取指标摘要"""
        summary = {}

        for key, count in self._counters.items():
            summary[key] = {"type": "counter", "value": count}

        for key, values in self._timings.items():
            sorted_values = sorted(values)
            summary[key] = {
                "type": "timing",
                "count": len(values),
                "avg": round(sum(values) / len(values), 2),
                "p50": sorted_values[len(values) // 2],
                "p95": sorted_values[int(len(values) * 0.95)],
                "p99": sorted_values[int(len(values) * 0.99)],
            }

        return summary

    def report(self):
        """输出报告"""
        uptime = time.time() - self._start_time
        summary = self.get_summary()

        print(f"=== AI 应用指标报告（运行 {uptime:.0f}s）===")
        for key, stats in summary.items():
            if stats["type"] == "counter":
                print(f"  {key}: {stats['value']}")
            else:
                print(f"  {key}: avg={stats['avg']}ms, p95={stats['p95']}ms, p99={stats['p99']}ms")


metrics = MetricsCollector()
```

### 3.3 集成到 LLM 调用

```python
async def monitored_llm_call(messages, **kwargs):
    model = kwargs.get("model", "claude-sonnet-4-6")
    request_id = kwargs.get("request_id", "unknown")

    metrics.increment("llm.request_total", tags={"model": model})
    start = time.time()

    try:
        response = await call_llm(messages, **kwargs)
        duration_ms = (time.time() - start) * 1000

        metrics.increment("llm.success_total", tags={"model": model})
        metrics.timing("llm.latency", duration_ms, tags={"model": model})
        metrics.increment("llm.tokens.input", response.usage.input_tokens, tags={"model": model})
        metrics.increment("llm.tokens.output", response.usage.output_tokens, tags={"model": model})

        return response

    except Exception as e:
        metrics.increment("llm.error_total", tags={"model": model, "error": type(e).__name__})
        raise
```

## 四、Tracing：链路追踪

### 4.1 为什么需要追踪

一个用户请求可能经过多个步骤：

```
用户提问
  → 输入 Guardrails（2ms）
    → Embedding 查询（150ms）
      → 向量检索（50ms）
        → Prompt 组装（1ms）
          → LLM 调用（2500ms）
            → 输出 Guardrails（3ms）
              → 返回响应
```

总共约 2700ms，但瓶颈在哪？没有追踪就不知道。

### 4.2 简易 Span 追踪

```python
import uuid
import time


class Span:
    def __init__(self, trace_id, name, parent_id=None):
        self.trace_id = trace_id
        self.span_id = str(uuid.uuid4())[:8]
        self.name = name
        self.parent_id = parent_id
        self.start_time = time.time()
        self.end_time = None
        self.attributes = {}

    def finish(self):
        self.end_time = time.time()

    @property
    def duration_ms(self):
        if self.end_time:
            return round((self.end_time - self.start_time) * 1000, 2)
        return None

    def to_dict(self):
        return {
            "trace_id": self.trace_id,
            "span_id": self.span_id,
            "parent_id": self.parent_id,
            "name": self.name,
            "duration_ms": self.duration_ms,
            "attributes": self.attributes,
        }


class Tracer:
    def __init__(self):
        self.traces: dict[str, list[Span]] = {}

    def start_trace(self, name):
        trace_id = str(uuid.uuid4())[:12]
        span = Span(trace_id, name)
        self.traces[trace_id] = [span]
        return trace_id, span

    def start_span(self, trace_id, name, parent_id=None):
        span = Span(trace_id, name, parent_id)
        if trace_id in self.traces:
            self.traces[trace_id].append(span)
        return span

    def get_trace(self, trace_id):
        if trace_id not in self.traces:
            return []
        return [s.to_dict() for s in self.traces[trace_id]]

    def print_trace(self, trace_id):
        """打印可读的追踪结果"""
        spans = self.get_trace(trace_id)
        if not spans:
            print(f"Trace {trace_id} 不存在")
            return

        total_duration = spans[0].get("duration_ms", 0)
        print(f"\n=== Trace: {trace_id} ({total_duration}ms) ===")

        for span in spans:
            indent = "  " if span["parent_id"] else ""
            print(f"{indent}→ {span['name']}: {span['duration_ms']}ms")
            for k, v in span.get("attributes", {}).items():
                print(f"{indent}    {k}: {v}")


tracer = Tracer()
```

### 4.3 追踪 RAG 请求

```python
async def traced_rag_request(question, vector_store):
    # 开始追踪
    trace_id, root_span = tracer.start_trace("rag_request")
    root_span.attributes["question_length"] = len(question)

    # Step 1: 输入检查
    span_input = tracer.start_span(trace_id, "input_guardrail")
    input_result = check_input(question)
    span_input.finish()

    if not input_result.passed:
        root_span.finish()
        return {"error": input_result.message}

    # Step 2: 向量检索
    span_search = tracer.start_span(trace_id, "vector_search")
    docs = vector_store.search(question, top_k=5)
    span_search.attributes["result_count"] = len(docs)
    span_search.finish()

    # Step 3: Prompt 组装
    span_prompt = tracer.start_span(trace_id, "prompt_assemble")
    context = "\n".join([d["content"] for d in docs])
    prompt = f"基于以下资料回答：\n{context}\n\n问题：{question}"
    span_prompt.attributes["context_length"] = len(context)
    span_prompt.finish()

    # Step 4: LLM 调用
    span_llm = tracer.start_span(trace_id, "llm_call")
    response = await call_llm([{"role": "user", "content": prompt}])
    span_llm.attributes["model"] = "claude-sonnet-4-6"
    span_llm.attributes["output_tokens"] = response.usage.output_tokens
    span_llm.finish()

    # Step 5: 输出检查
    span_output = tracer.start_span(trace_id, "output_guardrail")
    output_text = response.content[0].text
    span_output.finish()

    root_span.finish()

    # 打印追踪结果
    tracer.print_trace(trace_id)

    return {"answer": output_text, "trace_id": trace_id}
```

### 5.2 Express 中间件

```javascript
function aiLoggingMiddleware(req, res, next) {
  const requestId = crypto.randomUUID().slice(0, 12);
  const startTime = Date.now();

  // 注入到 request 对象
  req.requestId = requestId;
  req.aiMetrics = { startTime };

  // 记录请求
  logger.info('request.start', {
    requestId,
    method: req.method,
    path: req.path,
  });

  // 拦截响应
  const originalSend = res.send;
  res.send = function (data) {
    const duration = Date.now() - startTime;
    logger.info('request.end', {
      requestId,
      statusCode: res.statusCode,
      durationMs: duration,
    });
    originalSend.call(this, data);
  };

  next();
}

app.use(aiLoggingMiddleware);
```

## 七、最佳实践

### 7.1 日志分级

```
ERROR：需要立即处理（LLM 全部不可用、数据库挂了）
WARNING：需要关注（Fallback 触发、Token 超限、Guardrail 拦截）
INFO：正常业务日志（请求开始/结束、模型切换）
DEBUG：调试信息（完整 Prompt、完整响应）
```

### 7.2 不要记录敏感信息

```python
# 不好：记录完整对话内容
log.info("用户消息", content=messages)

# 好：只记录元数据
log.info("用户消息", message_count=len(messages), total_chars=sum(len(m["content"]) for m in messages))
```

### 7.3 日志保留策略

```
Debug 日志：保留 3 天
Info 日志：保留 30 天
Error 日志：保留 90 天
Metrics 数据：保留 1 年
```

## 小结

| 能力 | 作用 | 工具 |
|------|------|------|
| 结构化日志 | 记录每次 LLM 调用的详情 | Python logging / Winston |
| 指标收集 | 统计延迟、成功率、Token 用量 | 自建 Collector / Prometheus |
| 链路追踪 | 定位请求瓶颈 | 自建 Tracer / OpenTelemetry |
| 告警 | 异常情况及时通知 | AlertManager / Slack Webhook |

从结构化日志开始，逐步加入指标和追踪。不需要一开始就上 OpenTelemetry 等重量级方案——先让日志可搜索、可统计，比什么都重要。
