# 第六阶段学习总览：工程化 / 部署 / 优化

## 文档目标

第六阶段的核心目标是理解：

> 如何把 AI 应用从"能跑"变成"能上线"，让系统具备生产级的可靠性、可观测性和成本效率。

前五个阶段你已经学过：

- Stage 1：LLM 基础，让 AI 能对话
- Stage 2：Tool Calling，让 AI 能调用工具
- Stage 3：RAG，让 AI 能查资料
- Stage 4：Agent / Workflow，让 AI 能完成多步骤任务
- Stage 5：AI Tooling，让 AI 嵌入浏览器和编辑器

第六阶段进入 **工程化**。这一阶段不再关注"AI 能做什么"，而是关注"AI 系统怎么稳定运行"：

- 调用失败了怎么办？怎么自动重试和降级？
- Prompt 变了怎么追踪？出了问题怎么回滚？
- AI 输出了不该输出的内容怎么拦截？
- 调了多少次 API？花了多少钱？哪个环节最慢？
- 怎么把项目打包成 Docker 镜像，一键部署到服务器？

---

## 第六阶段要学什么

根据 `plan/目标清单.md`，第六阶段包含三条主线：

### 工程化

1. **Retry / Fallback**：LLM 调用失败时的重试策略和模型降级方案
2. **Prompt Version 管理**：Prompt 模板的版本追踪、A/B 测试和回滚
3. **Guardrails**：输入过滤、输出校验、内容安全防护
4. **日志监控**：请求日志、链路追踪、告警和可观测性

### 优化

5. **Token 优化**：压缩上下文、减少无效 Token、提高性价比
6. **Cache**：语义缓存、响应缓存、减少重复调用
7. **Cost Tracking**：费用统计、预算控制、调用审计

### 部署

8. **Docker**：容器化打包、镜像优化、Docker Compose 多服务编排
9. **Redis Queue**：异步任务队列、限流、削峰填谷
10. **CI/CD**：自动化测试、构建、发布流水线

对应的实践任务是：

> 将前面阶段的项目全部 Docker 化，加入日志系统、重试机制、Redis 异步任务和 Cost Monitor。

## 推荐学习顺序

建议按下面顺序学习：

1. 先理解 Retry / Fallback——这是最基础的生产保障
2. 学 Prompt 版本管理——让 Prompt 迭代可追溯
3. 学 Guardrails——给 AI 输出加安全网
4. 学日志监控——知道系统在干什么
5. 学 Token 优化和缓存——省钱提速
6. 学 Docker 容器化——标准化部署
7. 学 CI/CD——自动化发布流程
8. 综合实战：把前面的项目全部生产化

## 核心概念地图

```
AI 应用工程化
├── 可靠性
│   ├── Retry（指数退避重试）
│   ├── Fallback（模型降级）
│   └── Circuit Breaker（熔断器）
├── 可观测性
│   ├── Logging（请求/响应日志）
│   ├── Tracing（链路追踪）
│   └── Metrics（延迟/成功率/Token 用量）
├── 安全性
│   ├── Input Guardrails（输入过滤）
│   ├── Output Guardrails（输出校验）
│   └── Content Safety（内容安全）
├── 成本优化
│   ├── Token 优化（压缩/截断）
│   ├── Cache（语义缓存/响应缓存）
│   └── Cost Tracking（费用统计/预算控制）
└── 部署运维
    ├── Docker（容器化）
    ├── Redis Queue（异步任务）
    └── CI/CD（自动化流水线）
```
